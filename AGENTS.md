# Working instructions

- Read [README.md](README.md) and [RESUME.md](RESUME.md) when starting or resuming work. Follow their links to the authoritative planning records; disclose access gaps rather than inventing missing context.
- Preserve accepted, provisional and proposed distinctions. A documentation merge does not approve every design proposal it contains.
- Pair program through small changes: explain the behavior and relevant code before each meaningful change, run it where applicable, and discuss what was learned.
- Respect the approval boundaries recorded in RESUME.md and planning: obtain authorization for implementation increments, tool installation and IntelliJ configuration. Within an agreed increment, proceed with routine reversible steps without repeatedly asking. Commits/pushes and merges require explicit authorization; use branches and PRs.
- This repository is public. Keep private knowledge, credentials and private planning evidence out; link to authoritative records instead of copying their contents.
- Update RESUME.md after meaningful outcomes and before handoffs, following its checkpoint-maintenance guidance.
- Inspect applicable instructions, local changes and live Git state before acting. Never discard, reset or overwrite unrelated work.
